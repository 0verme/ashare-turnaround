# Historical PIT replay validation summary

This tracked file is the safe, contract-level summary for issue #32. Runtime
corpus artifacts are intentionally not committed. The measured local summary
is generated by `replay-validate` at
`docs/pit-replay-validation-summary.md` (or the `--summary` path) and is kept
separate from RAW data.

The final scope is two-layered. Layer 1 is an exhaustive, small monthly target
schedule; Layer 2 is the frozen representative full-evidence sample. A target
record is not a full artifact, and an unavailable/future/incomplete target is
never replaced by a current snapshot. The acceptance audit and exact sample
list are in [pit-replay-validation-scope-closure.md](pit-replay-validation-scope-closure.md)
and [pit-replay-validation-sample-v1.json](pit-replay-validation-sample-v1.json).

## Correctness-only findings

- Target selection and feature/PIT cutoffs are separate: `trade_cal` is read
  unprojected for target selection, while each target's feature frames remain
  bounded at its selected trading date (`2025-06` remains `20250616`).
- `ru_maxrss` is retained as `peak_rss_diagnostic_bytes`; live PSS/private and
  MemAvailable are hard resource metrics. Process swap, `SwapFree`, and net
  system swap growth are v3 soft warnings; only sustained vmstat swap I/O under
  low MemAvailable is a hard swap-pressure signal.

- Financial visibility is bounded by `actual_available_date <= as_of`, including
  the original/revised version boundary fixture.
- Market and benchmark evidence is bounded by the selected trading session.
- Missing benchmark evidence stays `UNKNOWN`; no stock-only fallback is used.
- Current `stock_basic` name/status/industry/board fields are
  `UNSUPPORTED_PIT` and are never backfilled into historical rows.
- Every candidate retains feature evidence, score partialness, coverage,
  confidence, unknown groups, ranking eligibility, rejection reasons, and
  provenance in the per-snapshot artifact.
- The fixed manual-review artifact contains Top-3, high-score ineligible,
  unknown-heavy, and universe-exclusion cases when available.

## Scope guard

This summary contains no forward-return evaluation, return metric, parameter or
weight tuning, Score v2, ablation, or production strategy claim. The bounded
repair is execution-only: snapshot-local indexes, reuse, and streaming
serialization preserve the existing PIT/evidence/score payload. It is an
information-availability and auditability gate only.
